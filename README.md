# PawNet-Website

Сайт PawNet на Cloudflare Workers: статика плюс небольшой Worker для `/api/ip`.

## Структура

```
public/                 — то, что деплоится
├── index.html          — лендинг            → /
├── ip.html             — «Твой IP-адрес»    → /ip
├── faq.html            — FAQ               → /faq      ⚠ тело ещё SVG
├── offer.html          — Публичная оферта   → /offer    ⚠ тело ещё SVG
├── privacy.html        — Политика           → /privacy  ⚠ тело ещё SVG
├── 404.html
├── css/                — fonts / base / landing / ip / doc
├── js/                 — main.js (меню, аккордеон, тарифы), ip.js
├── fonts/              — Geologica (вариативный, 100–900) и Dela Gothic One, субсеты
├── img/                — коты, волна, флаги стран
├── geo/                — гео-база для /api/ip, собирается скриптом, в git не лежит
├── favicon.svg         — логотип PawNet
├── robots.txt, sitemap.xml, _headers

src/index.js            — Worker: /api/ip + раздача ассетов
scripts/build-docs.py   — пересборка faq/offer/privacy из исходного экспорта
scripts/build-geo.py    — сборка public/geo/ из DB-IP Lite и GeoNames
scripts/stamp-assets.py — версии ?v=хэш в ссылках на стили
wrangler.toml           — конфиг
docs/source/            — исходный экспорт из Figma (все 5 страниц одним файлом)
```

## Разработка

```sh
npm install
npm run geo      # гео-база для /api/ip, ~100 МБ исходников, один раз
npm run dev      # http://localhost:8787
```

Локально запрос идёт в Worker напрямую, и `/api/ip` берёт гео из
`request.cf`. Чтобы проверить ветку «за CDN», передай адрес так, как его
передаёт CDN:

```sh
curl -H 'X-Forwarded-For: 77.88.55.88' http://localhost:8787/api/ip
```

⚠️ **Папка синхронизируется Nextcloud**, а он снимает бит выполнения с нативных
бинарников. Поэтому `node_modules` вынесен наружу симлинком:

```
node_modules -> ~/.cache/pawnet-website/node_modules
```

Если после `npm install` появились ошибки `EACCES … esbuild` или
`permission denied`, значит `node_modules` снова оказался внутри синхронизации —
повтори вынос:

```sh
mv node_modules ~/.cache/pawnet-website/node_modules
ln -s ~/.cache/pawnet-website/node_modules node_modules
```

По той же причине npm-скрипты зовут wrangler через `node`, а не через
`node_modules/.bin`.

## Деплой

```sh
npm run check    # проверка конфига без публикации
npm run deploy
```

Перед публикацией `npm run deploy` сам проставляет версии стилей
(`scripts/stamp-assets.py`) и собирает гео-базу, если её нет.

Сайт открывается на **`pawnet.cloud`**: на него указывают canonical,
`og:url`, `sitemap.xml` и `robots.txt`. У `pawnet.ink` DNS-записей нет —
пока canonical вёл туда, Google помечал страницы как «Вариант страницы
с тегом canonical» и в индекс не брал. Если сайт переедет на другой
домен, поменять его нужно во всех этих местах сразу (для faq/offer/privacy —
константа `SITE` в `scripts/build-docs.py`) и поставить 301 со старого.

## Состояние страниц

| Страница | Состояние |
|---|---|
| `/` | пересобрана настоящей вёрсткой, 18 КБ, переключатель срока работает |
| `/ip` | пересобрана, данные живые из Worker'а |
| `/faq` | настоящие шапка и подвал, тело ещё вектор, 3.9 МБ |
| `/offer` | то же + рабочее оглавление на 21 раздел, 17.7 МБ |
| `/privacy` | то же + оглавление на 18 разделов, 11.3 МБ |

У трёх последних страниц пересобраны только шапка и подвал: зашитые в макет
обрезаны через `viewBox`, вместо них подставлена настоящая вёрстка. Само тело
документа остаётся вектором — текст в нём не выделяется, не ищется и не виден
поисковикам.

Оглавление в оферте и политике работает поверх того списка, что нарисован в
макете: на его строки положены прозрачные ссылки. Так же сделана кнопка
«Написать в поддержку» на FAQ. Цели прокрутки расставлены в процентах от
высоты документа, поэтому переживают любое масштабирование.

Фигуры в экспорте стыкуются впритык, и при дробном масштабе на стыках
оставались волосяные линии. Сборщик закрывает их двумя приёмами: полосам
добавляется обводка в цвет собственной заливки, а под геройскую зону
подкладывается сплошной жёлтый прямоугольник, чтобы сглаженный край обрезки
смешивался с жёлтым, а не с тёмным фоном.

Пересобрать эти страницы из исходного экспорта: `python3 scripts/build-docs.py`.

## Сайт за CDN VK Cloud

Перед Cloudflare стоит CDN VK Cloud. Из-за этого в `CF-Connecting-IP`
приходит адрес узла CDN, а не посетителя, и `request.cf` описывает этот
узел. Worker разбирает цепочку заголовков прокси:

```
True-Client-IP  ->  X-Real-IP  ->  X-Forwarded-For[0]  ->  CF-Connecting-IP
```

Сработавший заголовок виден в ответе `/api/ip` в поле `via`, а флаг
`proxied` показывает, стоял ли перед нами прокси.

### Гео-данные за CDN

Страну, город и провайдера для чужого адреса Cloudflare не считает,
поэтому за CDN Worker ищет их сам — по своей базе в `public/geo/`. Адрес
посетителя никуда не уходит, что совпадает с Политикой
конфиденциальности. Откуда взяты данные, видно в поле `source` ответа:
`cloudflare` — прямое соединение, `db-ip` — своя база, `null` — не нашлось.

База собирается из открытых наборов под CC BY 4.0:

- **DB-IP Lite** — город, регион, страна и провайдер по диапазонам адресов;
- **GeoNames cities1000** — часовой пояс: у DB-IP есть только координаты,
  поясом места считается пояс ближайшего города той же страны.

Лицензия DB-IP требует ссылку «IP Geolocation by DB-IP» рядом с данными —
она стоит в подписи под карточками на `/ip`, её не убирать.

Только IPv4: у `pawnet.cloud` нет AAAA-записи, и через CDN посетитель
приходит по IPv4. Если AAAA появится, IPv6-посетители увидят прочерки
и подпись «не определяются».

Файлы базы лежат среди ассетов, но снаружи по `/geo/*` отвечает 404:
этот путь в `run_worker_first`, и Worker читает файлы сам через `ASSETS`.

DB-IP выпускает базу раз в месяц. Обновить и выкатить:

```sh
npm run geo && npm run deploy
```

Скачанные исходники кэшируются в `~/.cache/pawnet-website/geo-src/`.

Если когда-нибудь захочется данных самого Cloudflare, можно завести хост
мимо CDN (например `ip.pawnet.cloud` прямо на Worker) и прописать его на
странице — скрипт спросит его первым, при неудаче вернётся к `/api/ip`:

```html
<body data-ip-endpoint="https://ip.pawnet.cloud/api/ip">
```

### Кэш стилей и CDN

CDN VK Cloud кладёт в кэш **один** сжатый вариант файла и отдаёт его всем
подряд, не глядя на `Accept-Encoding`: `ip.css` и `doc.css` лежали там
сжатыми zstd, а Safari его не распаковывает. Вдобавок стили отдавались с
`immutable` на год без версии в имени, и после перевода заголовков на
Dela Gothic One посетители продолжали получать старый CSS с Geologica.

Поэтому:

- ссылки на стили идут с версией `?v=<хэш содержимого>` —
  `scripts/stamp-assets.py`, запускается перед деплоем сам;
- `/css/*` отдаются с `Cache-Control: private` — браузер кэширует их
  надолго, а CDN не хранит вовсе и каждый раз пропускает запрос в
  Cloudflare, который сжимает под конкретного клиента. HTML, JS и шрифты
  CDN и так не кэширует: у них `max-age=0`.

### Диагностика заголовков

Чтобы увидеть, что именно шлёт CDN, есть выключенный по умолчанию
эндпоинт. Включается секретом:

```sh
npx wrangler secret put DEBUG_TOKEN
curl "https://pawnet.cloud/api/debug-headers?token=<секрет>"
```

Без секрета отвечает 404. После проверки секрет лучше удалить:
`npx wrangler secret delete DEBUG_TOKEN`.
