# PawNet-Website

Сайт PawNet на Cloudflare Workers: статика плюс небольшой Worker для `/api/ip`.

## Структура

```
public/                 — то, что деплоится
├── index.html          — лендинг            → /
├── ip.html             — «Твой IP-адрес»    → /ip
├── faq.html            — FAQ               → /faq      ⚠ тело ещё SVG
├── offer.html          — Публичная оферта   → /offer    ⚠ тело ещё SVG
├── privacy.html        — Политика           → /privacy  ⚠ тело ещё SVG
├── 404.html
├── css/                — fonts / base / landing / ip / doc
├── js/                 — main.js (меню, аккордеон, тарифы), ip.js
├── fonts/              — Geologica и Dela Gothic One, локальные субсеты
├── img/                — коты, волна, флаги стран
├── favicon.svg         — логотип PawNet
├── robots.txt, sitemap.xml, _headers

src/index.js            — Worker: /api/ip + раздача ассетов
scripts/build-docs.py   — пересборка faq/offer/privacy из исходного экспорта
wrangler.toml           — конфиг
docs/source/            — исходный экспорт из Figma (все 5 страниц одним файлом)
```

## Разработка

```sh
npm install
npm run dev      # http://localhost:8787
```

⚠️ **Папка синхронизируется Nextcloud**, а он снимает бит выполнения с нативных
бинарников. Поэтому `node_modules` вынесен наружу симлинком:

```
node_modules -> ~/.cache/pawnet-website/node_modules
```

Если после `npm install` появились ошибки `EACCES … esbuild` или
`permission denied`, значит `node_modules` снова оказался внутри синхронизации —
повтори вынос:

```sh
mv node_modules ~/.cache/pawnet-website/node_modules
ln -s ~/.cache/pawnet-website/node_modules node_modules
```

По той же причине npm-скрипты зовут wrangler через `node`, а не через
`node_modules/.bin`.

## Деплой

```sh
npm run check    # проверка конфига без публикации
npm run deploy
```

Домен `pawnet.ink` привязывается в дашборде Cloudflare
(Workers → Settings → Domains & Routes) или через `routes` в `wrangler.toml`.

## Состояние страниц

| Страница | Состояние |
|---|---|
| `/` | пересобрана настоящей вёрсткой, 18 КБ, переключатель срока работает |
| `/ip` | пересобрана, данные живые из Worker'а |
| `/faq` | настоящие шапка и подвал, тело ещё вектор, 3.9 МБ |
| `/offer` | то же + рабочее оглавление на 21 раздел, 17.7 МБ |
| `/privacy` | то же + оглавление на 18 разделов, 11.3 МБ |

У трёх последних страниц пересобраны только шапка и подвал: зашитые в макет
обрезаны через `viewBox`, вместо них подставлена настоящая вёрстка. Само тело
документа остаётся вектором — текст в нём не выделяется, не ищется и не виден
поисковикам.

Оглавление в оферте и политике работает поверх того списка, что нарисован в
макете: на его строки положены прозрачные ссылки. Так же сделана кнопка
«Написать в поддержку» на FAQ. Цели прокрутки расставлены в процентах от
высоты документа, поэтому переживают любое масштабирование.

Фигуры в экспорте стыкуются впритык, и при дробном масштабе на стыках
оставались волосяные линии. Сборщик закрывает их двумя приёмами: полосам
добавляется обводка в цвет собственной заливки, а под геройскую зону
подкладывается сплошной жёлтый прямоугольник, чтобы сглаженный край обрезки
смешивался с жёлтым, а не с тёмным фоном.

Пересобрать эти страницы из исходного экспорта: `python3 scripts/build-docs.py`.

## Сайт за CDN VK Cloud

Перед Cloudflare стоит CDN VK Cloud. Из-за этого в `CF-Connecting-IP`
приходит адрес узла CDN, а не посетителя, и `request.cf` описывает этот
узел. Worker разбирает цепочку заголовков прокси:

```
True-Client-IP  ->  X-Real-IP  ->  X-Forwarded-For[0]  ->  CF-Connecting-IP
```

Сработавший заголовок виден в ответе `/api/ip` в поле `via`, а флаг
`proxied` показывает, стоял ли перед нами прокси. **Адрес** после этого
верный, а вот **гео-данные за CDN недоступны**: посчитать страну и
провайдера для чужого адреса Worker не может, поэтому они отдаются
пустыми, а страница показывает прочерки и поясняющую строку.

### Как вернуть гео-данные

Нужно, чтобы запрос за адресом шёл в Cloudflare напрямую, мимо CDN.
Любой из вариантов:

1. Исключить `/api/*` из CDN VK Cloud — тогда всё работает само.
2. Завести отдельный хост (например `ip.pawnet.cloud`), направить его
   прямо на Worker без CDN и прописать его на странице:

   ```html
   <body data-ip-endpoint="https://ip.pawnet.cloud/api/ip">
   ```

   Скрипт сначала спрашивает этот адрес, при неудаче откатывается на
   `/api/ip` того же домена.

Гео через сторонний сервис намеренно не делается: это означало бы
отправлять адреса посетителей наружу, что расходится с Политикой
конфиденциальности сервиса.

### Диагностика заголовков

Чтобы увидеть, что именно шлёт CDN, есть выключенный по умолчанию
эндпоинт. Включается секретом:

```sh
npx wrangler secret put DEBUG_TOKEN
curl "https://pawnet.cloud/api/debug-headers?token=<секрет>"
```

Без секрета отвечает 404. После проверки секрет лучше удалить:
`npx wrangler secret delete DEBUG_TOKEN`.
